# Scenario and test audit — 2026-11-12

This audit, started on 2026-11-11, read the 16 scenario files (85 scenarios), the 18 test modules, the A/B
protocol and the fixtures, and recomputed the reference values that no test covered.
The offline tests were sound; the weak points were the agent scenarios, which are scored
by hand, and the link between scenarios, fixtures and tests. This change adds nine
tests (141 to 150 on the audited tree, 156 with the descriptive-statistics skill merged
meanwhile in #49).

## What already held

- The offline suite passed: 141 tests, 23 skipped (live tests, Mapshaper not installed,
  IGN grids absent) with GDAL 3.13.3, PROJ 9.8.1, GeoPandas 1.2.0 and Shapely 2.1.2.
- Many tests execute the code blocks of the skill files instead of copies, assert values
  with explicit tolerances, work in temporary directories and use loopback servers rather
  than the network. Missing tools skip; broken tools fail.
- Reference values recomputed by hand matched the scenarios: CRS-02 without the grid
  (651311.67, 6861349.50 and 582460.95, 6275415.72), CRS-05 in EPSG:3857 (209 ha, 2.31
  times the Lambert-93 area), GVB-03 (307.4 + 11.8 = 319.2 m², and 1200 m² with `-spat`
  alone) and GEO-06 (1 accepted, 5 to review, 1 unmatched).
- The A/B bookkeeping was consistent: 149 runs per repetition, one matrix row per
  scenario, score-table totals equal to three times the positive scenarios.

## Defects found and fixed

1. **Wrong reference value in CRS-01.** The Lambert-93 coordinates quoted for the
   Réunion point (10179785, 546780) belong to point 3 of `points.csv` (GEO-03), not to
   the Réunion point of `points_gps.csv` used by CRS-01. Corrected to 10180452, 546433.
2. **Scenario fixtures never read by a test.** `classes_synthetic.asc` (RAS-06),
   `geocoded_synthetic.csv` (GEO-06), `elevation_points.csv` and
   `elevations_synthetic.json` (ALT-02) were not opened by any test: the tests used inline
   copies, so editing a fixture could silently break its scenario. `points_lambert2e.csv`
   (CRS-02) was in the same case. The raster and NTF tests now read the fixtures, and
   `test_enrichment.py` gains `test_scenario_geo06_fixture` and
   `test_scenario_alt02_fixtures`.
3. **Scenarios that could not be scored.** 23 of the 85 scenarios had no
   `**Expected skill:**` line and 38 had no checklist, although the scoring grid counts
   checklist items. They were mostly the four skills added on 2026-10-28 (INT, DLF, ALT,
   RTE), five later scenarios (GEO-06, RAS-06, WMS-05, WFS-03, WFS-07) and most negative
   scenarios. Every scenario now has both. The new checklist items restate the former
   one-line expectations and the skills' own rules; no expected behaviour was added.
4. **Negative scenarios without the excluded skill.** WFS-N1, GPD-N1 and the API Carto
   negative named the skill to load, but not the one to avoid. They now say
   `not` followed by the skill of their file.
5. **Order and numbering.** GEO-06, RAS-06, WMS-05 and WFS-07 came after a negative
   scenario; they now precede it. The only API Carto negative scenario was numbered
   `APC-N2` with no `APC-N1`; it is now `APC-N1`. The runner lists are grouped by skill.
6. **No automated guard.** Nothing checked the structure of a scenario, and the matrix,
   score table and run count of `ab-testing.md` were kept in step by hand.
   `test_scenarios.py` adds seven checks. Four injected defects (a wrong run count, a
   checklist removed, a matrix row renamed, a prompt naming a missing fixture) each made
   it fail.
7. **Documentation.** `tests/README.md` listed the files but did not explain the kinds of
   tests, which tests cover which skill, the anatomy of a scenario, how to run a single
   test or what each skip means. Its manual setup also started the agent inside the
   clone, where the root `CLAUDE.md` is loaded, contrary to the isolation principle of
   the A/B protocol. The README is reorganized around these questions and runs manual
   scenarios in a directory prepared by the runner.

8. **Descriptive-statistics scenarios.** The `geospatial-descriptive-statistics` skill
   (#49) was merged during the audit with one-line expectations. Its four GDS scenarios
   were brought to the same format when this change was rebased on it.

## Verification

- `python3 -m unittest discover -s tests -p 'test_*.py'`: 156 tests, 23 skipped, no
  failure, in the same environment, after the rebase on #49.
- The NTF test still skips locally (no IGN grid); the input it now reads from
  `points_lambert2e.csv` was checked to be byte-identical to the former inline input.
- `validate-skills.py` passes: 17 skills.

## Remaining limits

- **GPD-04 names no data.** The agent must build its own zones, so only the procedure is
  comparable. A concrete prompt on `saint_mande.geojson` and `mnt_dalles/`, with a
  repeated index, would make the result checkable.
- **VDQ-01 and VDQ-02 have no fixture.** A small GeoJSON with a bow-tie polygon, a null
  geometry, an empty polygon and a duplicate with reordered vertices would make them
  reproducible; `test_vector_quality.py` already builds such data in memory.
- **GEO-05 measures little.** It can be answered from memory in both modes.
- **GDS-01 and GDS-02 name no file.** The agent types the values into its own table;
  the skill's handling of a real layer (layer discovery, units, CRS) is not exercised.
- **Skills without offline tests.** `geopf-services` and `geopf-wms-wmts` are exercised
  only by live tests and agent scenarios.
- **Vertical transformation in CI.** CI has no RAF18 grid, so the CRS-04 regression
  never runs there; it ran locally on 2026-10-28.
- **No campaign yet.** The checklists are complete but have not been used to score a full
  A/B campaign; the first campaign should confirm that every item can be scored from
  `answer.md`, `commands.txt` and `output/`.
