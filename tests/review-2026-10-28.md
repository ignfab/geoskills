# Workflow enrichment and validation — 2026-10-28

The collection now has 14 skills. Four additions cover unfamiliar-file intake,
ready-made IGN packages, point/profile elevation and network routes/reachable areas.
Existing workflows now provide WFS count/ID checks, explicit geocoding review categories,
raster quality checks and consistent output reports. Polygon coverage checks from PR #37
are preserved.

## Automated evidence

- Metadata/link validator: 14 skills pass. The four new skills also pass the skill-creator
  validator. The already available Skills CLI 1.7.2 lists all 14 without installing skills.
- Local suite: `python3 -m unittest discover -s tests -p 'test_*.py' -v` collects 103
  individual tests in this environment, with 87 passing and 16 deliberately opt-in live
  tests skipped. The Mapshaper class is additionally skipped before collecting its three
  tests because the tool is absent locally (`unittest` reports 17 skip entries in total).
  Existing IGN grids were supplied
  through `PROJ_DATA`; both NTF and vertical checks ran successfully.
- Explicit live run: `GEOSKILLS_LIVE=1 python3 -m unittest discover -s tests -p 'test_live*.py' -v`
  passes all 16 tests, including the five new enrichment tests.
- Environment: GDAL 3.13.3, GeoPandas 1.2.0, Shapely 2.1.2. No software was installed for
  this work. Mapshaper remains required in the existing CI environment.
- A/B preparation covers 57 positive and 18 negative scenarios, or 132 directories per
  full repetition. That dry run calls no agent and does not score task success.
- [GitHub CI on the implementation commit](https://github.com/ignfab/geoskills/actions/runs/40722496253)
  passes: 106 individual tests, 85 passing and 21 skipped (16 live, four newer-GDAL commands,
  one unavailable RAF18 grid). All three Mapshaper tests run successfully there. CodeQL
  checks for Python and Actions also pass. The modern-GDAL and RAF18 checks skipped in CI
  were exercised locally as described above.

The new offline checks execute documented examples and actual curl transfers. They catch
missing/repeated WFS pages by exported counts and IDs, preserve geocoding rows and leading
zeros, reject malformed policy inputs, verify categorical values/grid/nodata, and exercise
the full GDAL COG validator against valid and invalid layouts. A loopback ZIP server checks
byte-for-byte resume and refusal to append a changed edition. Intake tests preserve source
bytes and leave a missing CRS unknown. Elevation/navigation recipes reject missing results,
reordered points, wrong geometry types, invalid metrics and unconfirmed output CRS.

The live checks discover service metadata before queries. They export three communes
through GDAL with page size 1, compare source IDs/counts with hits before and after, exercise
ECQL attribute and explicit-CRS BBOX predicates, and require malformed ECQL to fail. Other
probes cover catalogue pagination, two elevation points, 20 profile samples, a short walking
route and a five-minute reachable area. No bulk IGN archive was downloaded.

## Limits and deployment observations

- Counts and unique IDs cannot establish a transactional snapshot: records may change
  without changing the count. The checker reports `consistent`, not guaranteed completeness.
- Full COG validation needs GDAL >= 3.13 and matching Python bindings. Older installations
  skip that check and must not present a metadata marker as full structural validation.
- On this date, IGN's commune layer accepted attribute filters and BBOX with `CRS:84`,
  but `INTERSECTS(geometrie, SRID=4326;POINT(2.42 48.84))` with the same bounded commune
  predicate returned HTTP 500 with no body. EWKT compatibility remains unverified on that
  deployment. The skill retains the CRS-aware fallback and explains that BBOX is only an
  envelope predicate, not an equivalent replacement for arbitrary polygons.
- The current navigation capabilities did not advertise the OSRM resource used by some
  official examples. The successful probes selected an advertised compatible resource.
- Archive integrity/resume tests use a synthetic local ZIP. They do not establish that
  every remote server supports ranges or publishes checksums.
- The agent pilot has no without-skills baseline and is not a campaign-wide success rate.
  Download and routing positive agent scenarios remain available for a later campaign;
  their command/response workflows were exercised by automated tests here.
