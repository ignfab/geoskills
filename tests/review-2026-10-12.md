## Reproduced problems and changes

1. **False duplicate features.** For `(attributes A, geometry X)`, `(A, Y)`, `(B, X)` and
   `(B, Y)`, the old intersection of two duplicate masks flagged all four rows, although
   no attribute/geometry pair repeats. The recipe now compares attributes and normalized
   WKB together. Native values also avoid collisions between nulls and `"<NULL>"` or
   separator-containing strings. Regressions include genuine reversed-ring duplicates
   and exclude null/empty geometry from comparable features.
2. **Multiplied zonal results.** Joining statistics on a repeated index produced four rows
   from two zones. Results are now attached by position with length and column-collision
   checks, preserving both the source index and source attributes. Regressions run the
   actual reference snippets against filtered and repeated indices.
3. **Repair component loss.** A polygon with a collapsed spike becomes a Polygon plus a
   LineString in Python; `ogr2ogr -makevalid` removes the line. Instructions now make that
   choice explicit and require a compatible output schema. The behavior was reproduced
   locally and agrees with the [GDAL documentation](https://gdal.org/en/stable/programs/ogr2ogr.html#cmdoption-ogr2ogr-makevalid).
4. **Missing validation instructions.** GeoPandas lacked the required output-validation
   section and the explicit prohibition on agent-run installation. Added those, schema
   discovery, join-count checks and territorial CRS guidance. The repository validator
   now requires both prerequisite and output-validation sections outside code fences.
5. **Incomplete operational guidance.** Added concrete prerequisite commands for CRS,
   geocoding and quality workflows; single-query coordinate checks and CSV row accounting;
   confirmed-source CRS assignment; and bounded raster retries using fresh output paths.

The successful local runs used the pre-existing `geoskills-test` environment (GDAL 3.13.3,
GeoPandas 1.2.0, Shapely 2.1.2). The default environment's GDAL cannot start because of an
unresolved `sqlite3_total_changes64` symbol. Inherited GDAL/PROJ paths also pointed to that
default environment. Test commands used matching paths explicitly, without changing shell
configuration or package installations. The initial environment lacked IGN grids;
`fr_ign_gr3df97a.tif` and `fr_ign_RAF18.tif` were subsequently downloaded from
`https://cdn.proj.org/` into a temporary data directory alongside links to the environment's
PROJ metadata. Pointing `PROJ_DATA` there enabled both grid tests without installing software.
To reproduce with an existing compatible environment:

```bash
GEOSKILLS_ENV=/path/to/existing/environment
env -u GDAL_DRIVER_PATH \
  PATH="$GEOSKILLS_ENV/bin:/usr/bin:/bin" \
  PROJ_DATA="$GEOSKILLS_ENV/share/proj" \
  GDAL_DATA="$GEOSKILLS_ENV/share/gdal" PROJ_NETWORK=OFF \
  python -m unittest discover -s tests -p 'test_*.py' -v
```

For the two grid-dependent checks, set `PROJ_DATA` to a directory containing the
matching `proj.db` and the two IGN grids. Otherwise those tests skip explicitly.

The live calls additionally used `GEOSKILLS_LIVE=1` and the configured network proxy.
Connection attempts from the sandbox could not resolve the proxy; a direct connection
was refused. Using the configured proxy outside the sandbox succeeded.
