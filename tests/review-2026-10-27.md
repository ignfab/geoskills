# Test audit — 2026-10-27

The existing tests are useful regression and smoke checks, but a passing suite does not
prove that an agent selects the right skill or completes every documented workflow.
This audit adds **15 test methods** (12 offline, 3 live), taking collection from **56 to 71**,
and connects more assertions to the actual skill examples rather than copied recipes.

## Defects reproduced and fixed

1. **Empty polygons accepted after repair.** The polygon-only quarantine example checked
   geometry type alone. A `Polygon EMPTY` remained in the usable output. The regression
   initially failed with rows `[1, 2, 4]` instead of `[1, 2]`; the example now explicitly
   excludes null and empty geometry. The test also checks collapsed polygons, conservation
   of all rows between output and quarantine, and preservation of the source.
2. **Invalid A/B comparisons looked successful in the report.** A run without skills
   could explicitly load/read one, or attempt software installation, yet return success
   and leave the report's result column blank. Regressions reproduced all three cases.
   The runner now records `contaminated` and `comparable`, stops on these detected
   violations, and retains `INVALID` in the report. `ok` still means process completion;
   task correctness must be scored separately. Old summaries require `CHECK` review.

## Coverage assessment

| Skill or component | Evidence and improvements | Remaining limit |
| --- | --- | --- |
| `geopf-services` | New tests execute its three curl examples; validate WFS layer/CRS metadata, navigation operations/resources and download pagination attributes. | Other overview services and authenticated APIs are not exercised. |
| `geopf-geocoding` | Live address, CSV preservation/quality, reverse and true parcel geometry checks pass; CSV splitter regressions cover boundaries and malformed input. | No load testing or exhaustive index coverage. |
| `geopf-wfs-download` | Bounded residential-building extraction validates attributes, CRS, extent and non-empty geometries. | Does not establish completeness of a multi-page export. |
| `geopf-wms-wmts` | Live orthophoto, Plan IGN and numeric elevation checks pass. | Small extents only; no server load/retry campaign. |
| `geoserver-cql-filter` | Actual curl examples verify encoding, escaping, limits, layer order and HTTP failures using a loopback recorder. | No real GeoServer parser/datastore validation; request transport alone does not prove ECQL semantics. |
| `crs-reprojection-france` | Mainland, overseas, missing CRS, NTF and vertical control points pass. Added cardinality checks prevent silently truncated coordinate output from passing. | Grid checks remain conditional on local IGN grid availability. |
| `gdal-raster-basics` | Existing mosaic, clip, grid alignment, weighted average and zonal checks remain useful. A new test executes explicit nodata conversion with an untagged sentinel and a valid zero. | COG metadata is not a full COG validator; not every resampling method is exercised. |
| `geopandas-basics` | Actual join, nearest, overlay and buffer examples now cover boundary/unmatched/overlapping cases, metric units and attributes. Stronger round trips cover leading zeros, nulls and repeated indices. Statistics distinguish zero, nodata and outside, and reject wrong result counts. | Examples still require the caller to align CRSs and select appropriate operations. |
| `vector-data-quality` | Audit, repair and quarantine examples now execute directly; duplicate and collapsed-component regressions remain. The empty-polygon defect is fixed. | Per-feature validity does not prove polygon coverage topology. |
| `mapshaper-simplify` | Both entry commands now execute directly; independent assertions still check topology, feature/property retention, vertex reduction and metric displacement. | Mapshaper is absent locally; its three tests require the pinned CI environment. |
| A/B runner | Dry run covers all 103 scenario/mode directories. New tests cover reuse protection, independent prerequisite copies and invalid comparisons. | Fake CLI only; no measurement of agent selection, accuracy or paid-model cost. |

The spatial tests follow the [GeoPandas join contract](https://geopandas.org/en/stable/docs/reference/api/geopandas.sjoin.html);
the nodata test checks the [GDAL warp options](https://gdal.org/en/stable/programs/gdalwarp.html).
Expected results come from explicit synthetic geometry/pixel values, stored control
points or independently checked output properties, not only command exit codes.

## Verification

- **57 offline test methods passed** in the existing `geoskills-test` environment
  (GDAL 3.13.3, GeoPandas 1.2.0, Shapely 2.1.2), including NTF and vertical grid checks.
- **11 live test methods passed** against public IGN services. Only supplied public
  fixtures and bounded catalogue/download requests were used.
- **3 Mapshaper methods remain for CI**: no Mapshaper was installed locally. Unittest
  reports one class-level skip for these three methods, so subtracting its skip count
  from its `Ran` count is not a reliable passed-method count.
- Four temporary, in-memory mutations were rejected by the new tests: `left` → `inner`
  join, `within` → `intersects`, buffering without projection, and omission of source
  nodata. No mutated skill files were written.
- Cached Skills CLI: all **10 skills** discovered without installing them.
- The ordinary suite keeps live tests disabled. GitHub Actions now offers an explicit
  manual `live` option; pushes and pull requests keep using offline checks.

Official `fr_ign_gr3df97a.tif` and `fr_ign_RAF18.tif` data were fetched from
[the PROJ grid CDN](https://cdn.proj.org/) into a temporary directory with links to the
existing environment's PROJ metadata. Matching `PROJ_DATA`, `PROJ_LIB` and `GDAL_DATA`
were passed per command; no software or shell configuration was installed/changed.
See the [previous review](review-2026-10-12.md#verification) for the environment recipe.

For further evaluation, run the [manual agent scenarios](README.md#running-a-scenario)
and score their outputs using the [A/B protocol](ab-testing.md). The dry-run runner tests
validate that protocol's mechanics; they are not an agent-performance evaluation.
